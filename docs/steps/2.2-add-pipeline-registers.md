# Step 2.2: Add pipeline registers

Status: completed. Notes recorded November 13, 2026.

## Why we needed this

Shorter logic paths between registers may support a faster clock.

## What we did

We generated a second architecture with a register after each of the four logic layers.

## How it works

The same exporter uses --pipeline. Gate choices and connections stay the same, while each layer stores its output for the next clock. The valid indicator is delayed alongside the data.

## Small example

Like an assembly line, several images can occupy different stages at once.
This version has six register stages, while a new image can enter every cycle.
From the input capture edge, its output becomes available after five elapsed
clock periods; a downstream register captures it after six.

## Result and its limits

The stage count changes from 2 to 6. The corresponding input-capture-to-output
interval changes from 1 to 5 clock periods. That does not by itself establish
higher throughput: clock speed still needs implementation timing analysis.
See [step 2.10](2.10-compare-latency-and-throughput.md) for the precise latency
boundaries and the later head-pipelined variants.
