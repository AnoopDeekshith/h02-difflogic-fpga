# Step 3.4: Implement waveform activity analysis

Status: completed and independently verified. November 16, 2026.

## Why

A waveform viewer shows changes, but research needs a repeatable counter.
Counting changed bus records as one transition misses how many individual bits
changed. Counting every displayed name can also double-count VCD aliases.
Treating unknown initialization as binary activity would add artificial toggles.

This step implements the counter. It does not yet choose the useful-work
window, classify signals or establish a validated logical-network switching total.

## What changed

- [dlgn/vcd_activity.py](../../dlgn/vcd_activity.py): a streaming digital VCD
  parser/counter using only Python's standard library.
- [scripts/analyze_waveform.py](../../scripts/analyze_waveform.py): a fresh,
  capture-bound analysis report with hashes and preserved analyzer sources.
- Independent [tests](../../tests/test_vcd_activity.py) and
  [review](../reviews/step-3.4-independent-review.md).

No RTL, model, training protocol, clock or input sequence changed. The script
reads the step 3.3 files without modifying them and saves a new analysis folder.
It analyzes an existing capture; it does not report that capture as a new simulation.

## Counting rules, with examples

1. **Count bits, not bus records.** `0011 → 0101` is two known bit toggles:
   one rise and one fall. One bus update is a separate record-level statistic.
2. **Initialization is not switching.** The first recorded value of each
   identifier establishes its state. Unknown initial bits are recorded separately.
3. **Keep four-state information.** `0 → X → 1` produces zero known binary
   toggles and two unknown-involving bit changes. Do not bridge the unknown gap
   and invent a known `0 → 1` toggle. `X → Z` is one four-state change.
4. **Normalize short vectors.** A four-bit `b1` means `0001`; `bx1` means
   `xxx1`; `bz` means `zzzz`. Known values zero-extend, while a leading X/Z
   extends that state. Uppercase forms are accepted.
5. **Deduplicate true aliases by identifier.** Two declarations sharing the
   same ID and width have one counter and a list of names. Incompatible widths
   are rejected. Distinct IDs remain distinct even if their values are equal.
6. **Preserve recorded order.** `0 → 1 → 0` at one timestamp is two recorded
   toggles. These are file events, not proof of a physical glitch. Icarus
   writes each identifier at most once per timestamp (its final value), so
   real captures never contain such records; only synthetic tests do. Repeated
   assignments of the same normalized value are redundant records, not toggles.

The main invariant is:

```text
known_bit_toggles = rises + falls
four_state_bit_changes = known_bit_toggles + unknown_bit_changes
observed_records = initializations + value_change_records + redundant_value_records
```

Per-identifier counts preserve every alias, declaration width and hierarchical
name. Report paths retain declared range suffixes such as `top.bus[3:0]`;
the range is also recorded separately. `seconds_per_tick` is an exact decimal
string; integer timestamps plus the timescale magnitude/unit remain authoritative.

These digital four-state representations follow the VCD reader/writer model
documented by [PyVCD](https://pyvcd.readthedocs.io/en/stable/vcd.reader.html).
PyVCD is a format reference, not an installed runtime dependency here.

## Supported format and explicit rejection

The parser supports digital wire/reg/integer/parameter-style declarations,
hierarchy/ranges, scalar and binary vector records, integer timestamps,
multiline whitespace-separated directives/records, comments and dumpvars/dumpall
snapshots. Header scopes/definitions must close and a valid timescale is required.

Malformed data, undeclared IDs, incompatible aliases, oversized or invalid
binary values, backwards time, unclosed blocks and unsupported directives are
errors. Real/string/event encodings and dumping suspension (`dumpoff`/`dumpon`)
are rejected rather than silently dropped. This is a scoped digital parser,
not a claim of universal VCD compatibility. A malformed tail is rejected even
if it falls outside requested counting bounds.

## Window mechanics, without choosing the research window

Default analysis includes all recorded timestamps, including initialization at
time zero, reset, fill and drain. Initial values are still never toggles.

The API accepts optional `(start_tick, end_tick]` boundaries: changes at the
start are excluded; those at the end are included. The parser carries values
from before the start, so it neither initializes everything again nor invents
an edge at the boundary. Explicit start zero excludes all time-zero records;
an omitted start includes them. Units are VCD ticks, not assumed nanoseconds.
No time-normalized or per-image activity rate is reported.

These are tested boundary mechanics for future use. **Choosing and validating
equivalent useful-work windows remains step 3.5.**

## Run and reproduce

From the repository root:

```bash
.venv/bin/python scripts/analyze_waveform.py \
  runs/digits_w1000/baseline-waveform.xs90rtvt
.venv/bin/python -m pytest tests/test_vcd_activity.py -q
```

Each run creates `activity-analysis.<suffix>/result.json` under the capture
directory. The wrapper requires a passed full-capture manifest and verifies
all archived file hashes, including VCD, model, ordered inputs, parameters,
ledger and core. It checks VCD/manifest stability during analysis and preserves
an exact capture-manifest copy and both analyzer source files. Failed attempts
retain a failed report; earlier reports and capture files are not overwritten.
Raw analysis reports contain every ID's counts; the tracked summary is compact.

## Independent verification

The separate string-by-bit oracle agrees with every identifier's known,
unknown-involving and four-state counts on both full captures. Fresh independent
reports are `baseline-waveform.xs90rtvt/activity-analysis.57c50ob3/result.json`
and `baseline-waveform.q2umneq1/activity-analysis.hhsciw9w/result.json` under the
historical run. The first folder preserves `independent-verification.py` and
`independent-verification.json`, including checks of the root's primary report.
Every checked report's 16 capture artifact, three analysis artifact and two
analyzer source hashes passed. These are new analyses of existing captures,
not new RTL simulations.

All **35 independent tests** passed. The final full suite passed **130 tests in
10.16 seconds**, no skips. The [review](../reviews/step-3.4-independent-review.md)
found no blocking issue in this scope. Whole-file event-count agreement does
not replace the settled logical/Python comparison planned for 3.7.

## Debugging record

- **Expected versus actual:** the first independent regression run expected
  range-free alias paths and a floating-point time conversion. The implementation
  retained range-qualified names and an exact decimal string. Hand-counted
  transition totals already agreed; 22 tests passed and two metadata checks failed.
- **Reproduction:** `.venv/bin/python -m pytest tests/test_vcd_activity.py -q`
  with the initial expectations. The observed failure excerpt/summary is saved
  in `runs/step-3.4-debug/initial-test-observations.txt`.
- **Root cause:** test/implementation assumptions differed at the new report
  schema, not in bit/alias/unknown transition semantics.
- **Fix:** make those schema choices explicit and update the independent
  expectations; convert the decimal string when numerically comparing units.
  No counting constraint or transition rule was weakened.
- **Verification and prevention:** the aligned initial 24 cases passed; more
  independent fault/provenance cases were added. Preserve these schema checks
  and the invariants above. Final test results and oracle checks are in the review.

## Research assessment and next steps

- **Tested correctness:** hand-counted four-state/alias cases and independent
  oracle comparisons establish counter behavior within the supported format.
  Existing score/class equivalence remains the step 3.3 result.
- **Measurement proxy:** these are digital recorded-event counts. Steps
  3.5–3.6 must choose windows and categories, then 3.7 must align settled
  logical outputs against NumPy. Mapped activity remains 3.8.
- **Power/energy:** simulator event counts do not include routed capacitance or
  establish physical glitch activity, measured power or energy savings.
- **Research direction:** proceed conditionally with matched workloads and
  validation-selected repeated training. Neither regularizer effectiveness
  nor novelty is established by implementing this parser.
