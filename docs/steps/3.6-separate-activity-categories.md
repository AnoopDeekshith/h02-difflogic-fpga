# Step 3.6: Separate activity categories

Status: completed and independently verified.
November 16, 2026.

## Why separate the counts

A clock bit, a learned gate output, an output register and a testbench counter
serve different purposes. Adding all their changes gives a trace diagnostic,
but does not tell us how often the learned network changes between images.
The same logical information can also appear on several separately named buses.

For example, without layer pipeline registers, `l1` forwards `l1_c`. The
captured VCD gives them distinct identifiers, so both appear in the raw count.
We select **only `l1_c` through `l4_c`** for the learned gate-output metric.
With layer pipelining, `l1_c` is the combinational result and `l1` is the
following register; their roles and frame availability differ.

## What changed

Added [report_activity_categories.py](../../scripts/report_activity_categories.py).
It reads an existing step 3.3 capture, verifies its hashes, regenerates the
supported exporter structure in memory to check archived RTL/parameters, and
revalidates the step 3.5 workload/windows. It does not retrain, resimulate or
reroute the historical baseline. Earlier source and evidence remain intact.

Two separate reports answer different questions:

1. **Whole-trace categories:** partition every VCD identifier exactly once,
   including reset, initialization observations, fill, drain and bookkeeping.
   All counter fields reconcile with the step 3.4 whole-file diagnostic.
2. **Frame-aligned observations:** at each step 3.5 observation, count recorded
   events within its window and separately compare its 450 known endpoint
   values, retaining 449 adjacent-image pairs. Only canonical layer outputs
   enter the logical gate-output metric.

## Category rules and observability

| Category | Examples and interpretation |
|---|---|
| Logical layer output | `l1_c`–`lD_c`; one slot per learned gate |
| Logical layer copy | `l1`–`lD` with no layer registers; excluded from canonical metric |
| Layer register | `l1`–`lD` when layer pipelining is enabled |
| Input port | `x` |
| Data register | `l0`, registered `scores`, registered `class_out` |
| Head score-register view | `sc_flat` with head pipelining; packed observation of `sc_reg` |
| Output logic | Popcount `pc*`, winner-tree `win*`, `best`, and non-head `sc_flat`/`best_sc` |
| Clock | `clk` |
| Control | `rst`, `in_valid`, `out_valid`, `vpipe` (includes valid registers) |
| Elaboration constant | `LATENCY` |
| Simulator bookkeeping | Icarus loop-index integers under `$ivl_for_loop*` |
| Testbench | Transaction indices/counts, cycle index and completion marker |

Roles follow the verified exporter architecture, **not the VCD `reg` keyword**.
In particular `sc_flat` is built by `always_comb`; with head pipelining it
provides a packed view of the score bank, rather than another register bank.
Unpacked `sc`/`sc_reg` arrays are not separately observable in this capture.
The register category is therefore an RTL observation category, not a complete
physical flip-flop inventory or register power breakdown. Control registers
remain in control; the head bank is represented by its stated packed view.

True aliases sharing an identifier count once. A testbench alias of a DUT
signal belongs to its DUT role; a wire-only layer forwarding alias can share
its producer's logical-output role. Other conflicting role aliases fail.
Different IDs are retained even if their values agree. Unclassified names or
scopes fail rather than silently disappear. The actual full traces have no
shared-ID aliases; synthetic tests exercise alias behavior.

The head-only candidate has no layer registers, hence no separate layer-register
row in this table. It does contain the input, head and output register stages.

Settled canonical gate outputs, with exactly 449 adjacent-image pairs each:

| Layer observation | Bit changes | Changes / gate / image pair |
|---|---:|---:|
| `l1_c` | 126,546 | 0.28183964 |
| `l2_c` | 144,016 | 0.32074833 |
| `l3_c` | 167,436 | 0.37290869 |
| `l4_c` | 190,171 | 0.42354343 |
| **Logical comparison metric** | **628,169** | **0.34976002** |

The denominator is **4,000 logical gate slots × 449 image pairs = 1,796,000
bit-pair opportunities**. For example, settled states `001 → 101 → 100`
contain two bit changes across `3 bits × 2 pairs = 6` opportunities, a rate
of 1/3. The initial observation establishes state and contributes no toggle.

For this capture the recorded-event and settled counts agree on these layer
buses within their aligned windows, with no unknown-involving changes there.
This agreement is expected by construction rather than independent evidence:
Icarus records each identifier at most once per timestamp, so only changes
between timestamps (for example, between clock edges) can differ.
This does not establish absence of physical glitches. An intermediate recorded
pulse can increase event counts while the two sampled endpoints remain equal.
Known endpoints do not erase intermediate X/Z events; the raw counter retains
them separately. Output-tree nodes and other duplicate views are excluded from
the canonical layer denominator.

The aligned input/registered-input count is 22,013; the score-bank/output-score
count is 14,020 each; winner/output-class count is 788 each. These are separate
observations with their own widths and window offsets, not extra learned gates.
Do not sum them with layer counts and call the result device switching or energy.
Staggered windows preserve matching image pairs but are not one shared physical
time interval. The whole-trace table has a common recorded time span, but still
counts redundant RTL views rather than unique mapped physical nodes.

## Reproduce and evidence

From the repository root:

```bash
.venv/bin/python scripts/report_activity_categories.py \
  runs/digits_w1000/baseline-waveform.xs90rtvt
.venv/bin/python -m pytest tests/test_activity_categories.py -q
```

Primary report:
`runs/digits_w1000/baseline-waveform.xs90rtvt/activity-categories.w0799sk1/result.json`.
Each attempt saves the exact capture manifest and eight source copies/hashes,
with all 16 capture artifact hashes checked before and after analysis. Failure
reports are preserved in fresh attempt folders. Raw captures and reports are
gitignored local evidence; a fresh clone needs those artifacts or reproduced
captures. Synthetic regressions do not require the historical model.

Tracked [result summary](../results/step-3.6-activity-categories.json) and
[independent review](../reviews/step-3.6-independent-review.md) record final
verification evidence. Independent reports under the historical run:
`baseline-waveform.xs90rtvt/activity-categories.y98xlian/result.json` and
`baseline-waveform.q2umneq1/activity-categories.z_xyxdti/result.json`.

A separate line-based endpoint decoder and string-per-bit raw-event oracle
agree on the primary and both independent reports: every ID/category, 14
observations, settled counts and raw known/unknown changes. All 16 capture,
eight current-source and nine saved-analysis hashes per report pass, along
with exact saved-manifest identity. Audit script/JSON are preserved in
`activity-categories.y98xlian/independent-verification.{py,json}`; the audit
also pins its three independent test/oracle source hashes.

## Verification and research boundaries

The 20 independent focused tests passed in 0.92 seconds, no skips. They cover
all four layer/head register configurations, repeated frames, true aliases and
distinct-ID copies, ambiguous/unclassified observations, raw versus settled
known/X pulses, and preserved failed reports for hash, exporter, ledger and
required-evidence faults. The full suite passed **172 tests in 12.25 seconds,
no skips**. No unexpected failure or production correction was needed; no
blocking finding remains in the independent review.

- **Tested correctness:** accounting and frame-aligned counting of the saved RTL
  trace; direct layer-by-layer NumPy value/transition comparison remains 3.7.
- **Measurement proxy:** settled learned gate-output changes and categorized
  recorded events. This is standalone streaming at nominal 12 MHz (83,334 ps
  rounded period), not UART traffic, mapped nets or physical glitches.
- **Power/energy:** no power estimate or electrical measurement, no energy
  reduction and no regularizer benefit established. Count reductions alone
  would not establish lower energy.
- **Research direction:** continue to 3.7, then complementary metrics/matched
  training and mapped activity. Keep data order, architecture, clock and target
  matched; use validation for model selection. Historical inspected digits
  results remain exploratory, and novelty remains unverified.
