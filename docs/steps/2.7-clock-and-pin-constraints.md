# Step 2.7: Clock and pin constraints

Status: completed for constraint setup, synthesized connectivity review and
packing checks. Placement, routing and timing results remain step 2.8 onward.
Recorded November 13, 2026. No physical board was required.

## Why we needed this

Step [2.6](2.6-build-the-uart-interface.md) gave the design four external
signals. We now have to tell the implementation tool which physical pins they
use and how much time the clock gives the logic between register edges.

## What we did

We added an explicit 12 MHz clock constraint, integrated the existing pin file
into a repeatable nextpnr flow, and checked the mapped RX and reset circuits.
We also ran packing, which groups LUTs and registers into physical logic cells.
This stops before placement and routing when `--pack-only` is selected.

## How the clock and pins work

The [PCF file](../../synth/icebreaker_uart.pcf) maps names to package pins:

| Signal | SG48 pin | Purpose |
|---|---:|---|
| `clk` | 35 | Board oscillator |
| `button_n` | 10 | Active-low reset button |
| `uart_rx_pin` | 6 | Laptop-to-FPGA serial data |
| `uart_tx_pin` | 9 | FPGA-to-laptop serial data |

The [SDC file](../../synth/icebreaker_uart.sdc) contains:

```tcl
create_clock -name clk12 -period 83.333333333333 [get_ports clk]
```

At 12 MHz, each cycle lasts approximately 83.33 ns. The implementation flow
also sets a 12 MHz default target and fixes placement seed 1 for repeatability.
This sets a requirement; it does not mean the DLGN already meets it.

## What we checked about asynchronous inputs

The serial input and push button can change at any point within a clock cycle.
They are not additional clocks.

- RX goes into `rx_meta`, then `rx_sync`, both clocked by `clk`. Only the second
  stage feeds the receiving logic. The first stage's output feeds only the
  second stage's data input.
- Button reset asserts asynchronously. Two registers shift the release through
  the clock domain before the adapter leaves reset. In Yosys's mapped netlist,
  these appear as two `SB_DFFR` registers with inverted reset state encoding.
- The checker inspects actual register connections in `synth_uart.json`; it
  does not merely look for a comment or an `async_reg` attribute.

For example, if RX changes just as the clock rises, the first register may not
settle immediately. The second stage provides additional settling time before
the rest of the receiver uses the value. This reduces the risk; simulation does
not model metastability or establish a failure probability. Physical placement
and timing review remain necessary.

We did **not** invent clock-relative input/output delays for an asynchronous
UART peer. We did not mask internal timing paths. The upstream nextpnr generic
SDC parser reports `set_false_path` as having no effect, so this flow uses no
such exceptions. Its clocked timing reports are not a complete asynchronous
interface, reset-recovery or metastability signoff.

## How to run the checks

Run from the repository root, after exporting and synthesizing the UART design:

```bash
bash synth/implement_uart_ice40.sh runs/digits_w1000/uart_comb --pack-only
bash synth/implement_uart_ice40.sh runs/digits_w1000/uart_pipe --pack-only
.venv/bin/python -m pytest tests/test_constraints.py -q
```

The script reads the current repository PCF/SDC, checks them against the
synthesized design, and copies them into the run directory. It fails on missing
or incorrect pins, a wrong clock period, unexpected timing exceptions, or an
incorrect synchronizer connection. This checker intentionally expects the
current Yosys mapping; a future mapping change needs review rather than silently
passing an unrecognized circuit.

After packing, it checks every reported resource category against capacity.
If capacity is exceeded, it saves the report and exits with code **3**.
The pipelined command above currently has that expected outcome.

## Results and the important discovery

Both architectures accepted the clock and pin constraints. Their logs explicitly
show `clk` constrained to 12.00 MHz and all four I/O pins assigned.

| UART design | Packed logic cells | Available | Interpretation |
|---|---:|---:|---|
| Original | 3,795 | 5,280 | Within this resource count; routing still unproven |
| Pipelined | 6,236 | 5,280 | Cannot fit this target as currently built |

Why did the pipeline look smaller in [step 2.4](2.4-synthesize-the-pipelined-core.md)?
Synthesis counted LUTs and flip-flops separately. Some share one physical cell,
but not every register can share with a LUT. The UART also adds hardware.
Packing exposes the actual cell requirement before placement.

Each run folder contains `constraint_audit.json`, `pack_uart.log`,
`pack_uart_report.json`, `packed_uart.json`, and the copied PCF/SDC files.
The audit distinguishes correct constraints from exceeding resource capacity.

Six focused regression cases cover a correct synthesized wrapper, a missing
pin, a wrong clock/unsupported exception, an unexpected register clock, an RX
synchronizer bypass and a reset stage removal. Deliberately broken cases must
be rejected.
