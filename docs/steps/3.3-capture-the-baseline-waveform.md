# Step 3.3: Capture the full baseline waveform

Status: completed and independently verified. November 16, 2026.

## Why

Step 3.2 checked that recording works on eight images. Now we need a complete,
reproducible trace before implementing the activity counter. Otherwise a later
change in image order or workload could look like a benefit from training.

## What is frozen

| Setting | This capture |
|---|---|
| Model | Historical unpenalized `runs/digits_w1000/model.json`; no retraining |
| Data | All 450 rows of saved `x_test_bits.npy`, unchanged order, 192 bits/image |
| Architecture | Four 1,000-gate layers; head-only pipeline; 3 register stages |
| Hardware association | Core regenerated byte-for-byte from model and matched to `uart_comb_head` and its saved passing implementation |
| Clock | Nominal 12 MHz; fixed 41,667 ps half-period at 1 ps simulation precision |
| Interface/workload | Standalone core; one image per clock, no bubbles; not serial UART |
| Reset and drain | Three initial clock cycles; hold last input after valid drops; three falling edges after final output check |
| Oracle | Fresh NumPy integer scores and lowest-index argmax for every input |

The simulated period is **83,334 ps**, or **11,999,904.000768 Hz**, because
83,333.333… ps is not an integer number of 1 ps ticks. This is a declared
simulation rounding choice, not a changed FPGA timing constraint or a physical
clock measurement. Future matched captures must reuse the same choice.
The existing implementation's target remains 12 MHz. No new synthesis or
placement/routing was performed in this step.

The original non-head design failed the 12 MHz timing target. We therefore use
the feasible head-only candidate as the hardware-associated baseline. Its
logical gate rules still belong to the historical unpenalized model. The
oversized full-layer pipeline remains rejected; it is not a second implemented
comparison. This capture is not the UART board workload even though the core
is bound to that board export.

## How

[capture_baseline_waveform.py](../../scripts/capture_baseline_waveform.py)
creates a fresh `baseline-waveform.<suffix>/` directory and:

1. Checks the selected export and archived implementation evidence, then
   regenerates the exact head-only core from the supplied model.
2. Copies model/inputs, saves all original row indices, and creates fresh input,
   score and class hex files. All saved rows are used; there is no subset flag.
3. Compiles [tb_activity_capture.sv](../../rtl/tb_activity_capture.sv) with
   Icarus. Input/reset changes occur at falling edges. Every output is checked
   1 ps after the rising edge so nonblocking register updates have settled.
4. Records the complete DUT plus input/output indices, counters, cycle index
   and `capture_done`. `events.csv` logs every capture/check boundary.
5. Checks all 450 outputs, event count/order/cadence/latency and required VCD
   observability. The raw trace retains startup and drain.
6. Saves commands, executable versions/hashes, source/artifact hashes and final
   pass/fail status. Failed attempts are retained rather than overwritten.

No inference RTL or training code was changed. The capture bench is separate
from the old nominal-100-MHz smoke bench, which keeps its earlier meaning.
The recorder uses the step 3.2 observability inspector on these varied saved
images; its input-change requirement is not a general transaction counter.
Repeated image values are legal in the bench; indices establish transactions.

## Small example: why the index matters

For image 0, the input register captures at **291,669 ps**. The three-stage core
has its output available two clocks later, at **458,337 ps**. The bench checks
it at **458,338 ps**, after register updates settle, and records output index 0.
The next image follows one clock later. Even two identical neighboring images
are two transactions; a signal need not toggle to represent a valid image.

The extra 1 ps is a testbench observation offset, not another register stage
or measured physical propagation delay.

## Reproduce

From the repository root:

```bash
.venv/bin/python scripts/capture_baseline_waveform.py runs/digits_w1000 \
  --export runs/digits_w1000/uart_comb_head \
  --implementation runs/digits_w1000/uart_comb_head/implementation.UVAx2g
.venv/bin/python -m pytest tests/test_baseline_waveform.py -q
```

This prints a fresh attempt path. It requires NumPy, Icarus, and the local
historical model/input/implementation artifacts. The source walkthrough and
summary are tracked; raw captures remain local and gitignored pending 7.3.

Open that attempt's `dlgn.vcd` in VS Code with VaporView, or in Surfer. The
earlier eight-image trace is still present and must not be labeled as this
new full capture. In VaporView, add signals under `tb_capture.dut`; transaction
markers are directly under `tb_capture`.

Independent full capture:
`runs/digits_w1000/baseline-waveform.q2umneq1/result.json`. A separate decoder
checked every recorded input word, score/class output and transaction marker
in both captures, exact reset/drain boundaries and 457 rising edges at the
declared period. All 13 source, 16 artifact and two executable hashes per
attempt passed. The independent audit script and result are preserved as
`independent-verification.py` and `independent-verification.json` in that folder.

Ten independent regressions passed: five simulation cases cover all four
register configurations plus repeated zero inputs/tied scores; five fault
cases reject corrupted event ledgers. The full suite passed **95 tests in
10.83 seconds**, no skips. No blocking finding remained in this capture scope.

## Evidence boundaries and research direction

- **Correctness:** integer score/class comparisons passed for the complete
  saved workload. This is finite testing, not formal equivalence.
- **Activity:** this is zero-delay RTL recording. No waveform transition total,
  alias/unknown accounting, category totals or Python/RTL activity agreement is
  claimed yet. Those remain 3.4–3.7, with complementary metrics in 3.10.
- **Hardware:** the source is tied to the feasible saved candidate, but this
  is not a new routed-delay trace, UART measurement or physical-board run.
  Simulator events do not establish physical glitches.
- **Power/energy:** no device power estimate or electrical measurement exists.
  Fewer logical transitions, if later demonstrated, will remain a proxy until
  supported by separate power/energy evidence.
- **Research:** proceed with matched settings and validation-selected repeated
  training experiments. This historical test pool is already inspected and
  remains exploratory. Neither regularizer benefit nor novelty is established
  by capturing this baseline.
