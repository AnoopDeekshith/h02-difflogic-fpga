# Step 3.9: Assess glitch activity

Status: complete; independently verified ([review](../reviews/step-3.9-independent-review.md)).
November 16, 2026.

## Why

Steps [3.7](3.7-cross-check-numpy-and-rtl-activity.md) and
[3.8](3.8-measure-mapped-activity.md) counted **settled** changes: one value per
signal per clock cycle. Real logic does not switch once. When the two inputs
of a LUT arrive at different times, its output can flip, flip back, and only
then settle. Those extra flips are **glitches**. They cost dynamic energy but
are invisible in zero-delay simulation.

## What is measured

For every driven net bit of the **routed** iCE40UP5K UART board design (the
archived, verified head-only candidate from [step 2.8](2.8-place-and-route.md)):

- **timed transitions:** every value change with nextpnr's post-route delays
- **settled changes:** the value 1 ps before each rising clock edge, compared
  with the previous cycle
- **extra transitions** = timed transitions − settled changes (the glitch estimate)

The same netlist also runs at zero delay. Its settled values must match the
timed run bit for bit, so the delays change *when* nets switch, not *what*
the circuit computes.

## How

1. `scripts/capture_timed_activity.py` re-runs nextpnr on the archived inputs
   with `--sdf`. The new bitstream must be **byte-identical** to the archived
   one (SHA-256 `dcbc3c66…`), so the SDF delays belong to the verified design.
2. Icarus cannot parse nextpnr's escaped names (`\$`, `\[`), so all 4,169 cells
   are renamed `c0`, `c1`, …, consistently in netlist and SDF. Any SDF name
   that is not a known cell stops the run.
3. A generated testbench sends N clean UART requests at 12 MHz with the real
   104-clock bit divider. It checks every reply byte against NumPy, and counts
   transitions and settled changes for each net in the testbench itself (no
   giant waveform file).
4. Timed build: `-gspecify -ginterconnect -DTIMING` plus `$sdf_annotate`.
   `TIMING` selects the library's zero-default timing paths, so every delay
   comes from the SDF. Untimed build: no delays.
5. Checks: all replies correct in both runs; settled counts identical; no event
   within 10 ns of a sample point; per net, extra transitions are non-negative
   and even (a glitch is a there-and-back pair).

## Example

A tiny test circuit makes this concrete: `y = q XOR delayed(q)`, with the
delayed copy 3 ns late. Every clock, `q` flips, `y` goes 0→1 after 0.5 ns, then
back 1→0 after 3.5 ns. Settled `y` is always 0, so it has **2 extra transitions
per cycle and 0 settled changes**. The test checks exactly that.

## Evidence

Run: `runs/step3.9-glitch/timed-activity.0hvnej44/result.json`
([tracked summary](../results/step-3.9-timed-activity.json)). First 8 images in
saved order, 325,680 sampled clock cycles, 4,323 net bits (4,321 plus 2 clock nets).

| Category | Nets | Timed transitions | Settled changes | Extra | Extra per settled |
|---|---:|---:|---:|---:|---:|
| core (DLGN logic, scores, argmax) | 3,252 | 32,580 | 12,178 | 20,402 | **1.68** |
| interface (UART, adapter) | 1,022 | 2,923,403 | 1,723,025 | 1,200,378 | 0.70 |
| unclassified (reset chain, TX pin, VCC, interface carry cells) | 41 | 529,032 | 528,932 | 100 | 0.0002 |
| global buffers, I/O | 6 | 1,364 | 1,364 | 0 | 0 |
| **total (excluding clock)** | 4,321 | 3,486,379 | 2,265,499 | 1,220,880 | 0.54 |

- 1,897 of 3,252 core nets glitch at least once.
- All 8 replies are bit-exact, and settled values match between the timed and zero-delay runs.
- The latest event lands 51,369 ps after the clock edge. That is below the
  51.584 ns worst path from [step 2.9](2.9-read-and-verify-clock-timing.md),
  which is a plausibility check only, not an exact match.
- The verifier checked delays directly. All 14,835 observed flip-flop
  clock-to-output delays and all sampled LUT, carry and interconnect arrivals
  equal their SDF values.
- The clock is reported separately (2 nets, 1,302,720 edges) and left out of the totals.

Interpretation: in this routed core, on these 8 images, roughly **2.7 timed
transitions occur per settled change**. For the same nets and workload, a
zero-delay count would miss about 63% of transitions. That ratio is not a
direct correction for 3.7 or 3.8, which use different designs and workloads.

Classification risk: four nets named `board.adapter.core.out_valid_*` behave
like adapter logic. Moving them to the interface category raises the core
ratio from 1.68 to about 1.81. The "unclassified" group's roughly 529k settled
changes are really interface activity.

Tests: `tests/test_timed_activity.py` covers renaming, the ledger, the
arithmetic, the exact hazard circuit and the guard band.

## Limits

- **Inertial filtering:** Icarus swallows pulses narrower than a path delay. In
  a probe, a 200 ps pulse through a 300 ps interconnect and a 50 ps pulse were
  dropped, while 800 ps passed. Real silicon may pass some narrow pulses, so
  this count is model-dependent rather than a strict bound. The probe is saved
  as `test_icarus_filters_narrow_pulses_inertially`.
- **Delays:** one nextpnr delay corner. There are no setup/hold checks, because
  Icarus does not support SDF TIMINGCHECK.
- **Design:** this is the routed UART **board**, not the standalone core of 3.3–3.8.
  Most interface transitions come from the UART running between images.
- **Sample size:** only 8 images. The full 450 would take about 2.4 hours.
- **Scope:** no power or energy, and no capacitance weighting. This is the
  historical exploratory model, not a matched control.

Reproduce: `.venv/bin/python scripts/capture_timed_activity.py --n 8` (about 5 min).
