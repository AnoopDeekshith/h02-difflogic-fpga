# Step 3.5: Define and verify the measurement windows

Status: completed and independently verified. November 16, 2026.

## Why one global crop is insufficient

The first image takes time to reach each pipeline register. If we crop every
signal using the input register's timestamps, the output still contains older
invalid data at the beginning, and its final images fall beyond the crop.
Cropping only to when all stages are busy instead discards different end images
at different stages. Neither choice represents the same complete workload.

We therefore define **per-observation frame-aligned windows**. Each contains
450 known settled image states and the same 449 neighboring-image intervals:
0→1, 1→2, …, 448→449. Image 0 establishes the baseline; changing from startup
into image 0 is excluded. Pipeline fill and drain are handled by shifting the
windows to each observation's availability, rather than removing valid end images.

These staggered windows are not one shared physical-time interval. Their event
totals must not later be summed and presented as device-wide power or energy.

## What changed

Added [report_activity_windows.py](../../scripts/report_activity_windows.py).
It derives register offsets, checks the actual capture protocol and saves
fresh window reports. Existing captures, inference RTL, model, input order,
clock constraints and earlier analysis sources remain unchanged.

The supported workload is the fixed step 3.3 standalone streaming core:
three initial reset cycles, falling-edge input drive, no valid bubbles, an
83,334 ps simulated period, checks 1 ps after rising edges, and held final
input throughout drain. This is nominal 12 MHz rounded to a 1 ps grid, not
UART traffic or a new physical clock measurement.

## Endpoint convention and concrete example

For an observation with first-frame availability `a0` and last-frame
availability `a449`, sample at `a0+1 ps` and every clock thereafter. Use:

```text
(first settled sample, last settled sample]
```

The opening boundary is excluded from transition counts, but its value is
carried as the baseline by the step 3.4 counter. The closing boundary is
included. Samples at times with no explicit VCD timestamp carry the most
recent value, including all records at the requested time.

For example, image 0 enters `l0` at 291,669 ps. We sample it at 291,670 ps.
Image 449 is sampled at 37,708,636 ps. The window between those states contains
449 image intervals and excludes the initialization-to-image-0 change.
The registered score/class windows shift two clocks later, retaining the
same image pairs. The extra 1 ps is a testbench observation offset, not an
additional stage or measured physical propagation delay.

## Verified windows for the current head-only candidate

| Observation | Start, excluded (ps) | End, included (ps) | States / adjacent pairs |
|---|---:|---:|---:|
| Raw input port `x` | 250,003 | 37,666,969 | 450 / 449 |
| Input register `l0` | 291,670 | 37,708,636 | 450 / 449 |
| Every logical layer `l1`–`l4` and `l1_c`–`l4_c` | 291,670 | 37,708,636 | 450 / 449 |
| Head score-bank view `sc_flat` and winner `best` | 375,004 | 37,791,970 | 450 / 449 |
| Registered `scores` and `class_out` | 458,338 | 37,875,304 | 450 / 449 |

All windows span **37,416,966 ps = 37.416966 µs**, exactly 449 simulated
periods. This is an adjacent-state comparison duration, not the time to process
450 images from an empty pipeline and not an energy-per-prediction denominator.
Do not divide by 450 when reporting a rate per neighboring-image transition.
No activity rate or transition total is computed by this report.

For a layer-pipelined export, `lD_c` is available one clock before registered
`lD`. The script derives those offsets separately, also handling presence or
absence of the head bank. Independent toy tests cover all four register
configurations; they do not establish physical fit/timing for the oversized
full-layer FPGA candidate.

## How the window is validated

1. Verify every capture artifact hash and passed manifest. Check archived
   parameters, all row indices and reference-vector counts.
2. Check the ledger's input/output order, cadence and latency against capture
   metadata, including the three-cycle reset and complete final drain.
3. Parse the entire VCD using the step 3.4 format checks. Independently locate
   the required declarations and require the expected widths and 1 ps units.
4. Check all recorded clock edges, reset transitions and valid transitions.
   Reset must remain low throughout retained work, with no hidden pulses.
5. Check **every raw input-port change**, not only sampled endpoints: changes
   must exactly match the saved image values at falling edges. Repeated image
   values are legal and introduce no new data change. No extra off-phase or
   drain changes are allowed.
6. Verify every input/output transaction marker and all 450 endpoint samples
   per observation. All sampled stage values must be known. Recorded input,
   packed scores and classes must match the archived references at their
   respective availability times. Layer values are not yet compared to NumPy.
7. Recheck capture stability, then save the policy, source/manifest copies,
   per-signal endpoints, identifiers and provenance in a fresh attempt folder.
   Failed attempts remain available.

Known endpoint checks do not prove there were no intermediate layer events or
X/Z states between samples. The step 3.4 raw-event counter retains those
distinctions. Settled-state switching and category accounting remain 3.6–3.7.

## Finite-burst envelope is a separate concept

The report also records first data drive (250,002 ps) through final output
check (37,875,304 ps) as a **diagnostic burst envelope**. It includes the initial
processing and final in-flight image completions necessary for this finite
workload. It is not interchangeable with the staggered adjacent-state windows.

Power/energy work must use an actual common physical-time interval and count
completed predictions within that same interval, stating idle/reset and
fill/drain treatment. This step does not approve the burst envelope as a power
integration window or establish a power/energy denominator.

## Debugging and prevention

**Report schema.** The initial API descriptions conflicted about top-level
versus nested fields. Five of 17 tests raised `KeyError('windows')` after
successful validation. The wrapper was corrected to expose validated fields
at top level, matching the originally proposed API and independent tests.
All 17 then passed; no timing or test assertion was weakened. The initial
observations are preserved in `runs/step-3.5-debug/initial-test-observations.txt`.
Earlier preliminary report schemas remain in their original attempt folders.

**Off-phase input pulses: expected versus actual.** The protocol requires
falling-edge-only image changes and a held final input. Initial validation
checked inputs only at selected endpoints and at the end of drain. Independent
tests inserted 1 ps pulses between samples and during drain, restored the input,
and rebound the trace hash. Both malformed workloads were incorrectly accepted.

**Reproduction and root cause.** Run
`.venv/bin/python -m pytest tests/test_activity_windows.py -q` with the earlier
validator: `x_between_samples` and `x_during_drain` failed (20 passed, 2 failed).
The independent failing captures and original reports/source copies are in
`runs/step-3.5-verifier-debug/`. A separate root reproduction in
`runs/step-3.5-debug/off-phase-reproduction.yjmelv2x/` preserves the false
acceptance and a later `corrected-verification.json` documenting rejection.
The root cause was incomplete temporal protocol validation: endpoint equality
does not imply stable or correctly phased input data between endpoints.

**Fix and verification.** Track every normalized input-port value change and
require the exact expected falling-edge schedule, including initial state and
held-input drain. Legitimate repeated values remain valid transactions.
The expanded 22 tests passed in the root's focused rerun (0.79 s), including
both pulse cases. The independent verifier separately reran all 22 cases
(0.78 s) and rechecked both preserved originally accepted pulse captures;
both are now rejected. The recheck is recorded in
`runs/step-3.5-verifier-debug/corrected-verification.json`.
Keep those rebound-hash semantic fault tests to prevent
regression; hash verification alone would not catch the methodological defect.

## Research assessment

- **Tested correctness:** window/marker/control alignment and known endpoints
  are validated within the supported fixed workload. Score/class references
  retain the NumPy equivalence established by the capture step.
- **Measurement proxy:** this establishes comparable adjacent-image windows,
  not physical-net activity or a summed network switching result. Same-time
  simulator events are not measured glitches. Logical copies with different
  IDs still need deliberate category selection in 3.6.
- **Next:** separate categories in 3.6, then compare corresponding settled
  logical outputs and transitions against NumPy in 3.7.
- **Power/energy and research:** no lower-power or energy benefit, regularizer
  effectiveness or novelty is demonstrated. Keep targets, clock, architecture,
  input order and workload matched; select training settings on validation.
  The already inspected historical digits data remain exploratory.
