# Step 4.3: Run the initial penalty experiment

Status: complete; independently verified ([review](../reviews/step-4.3-independent-review.md)).
Recorded November 18, 2026.

## What happened

We trained a fresh unpenalized control and a matched model with activity-penalty
weight **lambda = 0.1**. The penalized model had **7.21 percent fewer settled
validation gate-output changes**, but recognized **four fewer validation
images**, an accuracy loss of **1.48 percentage points**. This exceeds the
predeclared one-percentage-point allowance, so the selector chose the control.

This is a valid accuracy/switching tradeoff result. It is not an accepted
optimization under our policy, and it does not establish lower energy.

## Why we ran this pair

[Step 4.10](4.10-prepare-validation-only-selection.md) established a workflow
that selects models using validation data while deferring test evaluation.
Its one-epoch runs checked the mechanism. This step runs the first matched
**60-epoch** pair to see what the penalty does after a meaningful fixed budget.

The loss adds `lambda × mean[2p(1-p)]` to classification loss, where each gate's
`p` is its batch-mean soft output. Lambda zero removes that pressure; lambda
0.1 adds it. The intended question is whether the hard network switches less
without exceeding the allowed recognition loss.

The historical **93.56 percent test accuracy** from `runs/digits_w1000` is not
the control. It used a different training protocol and evaluated a different
partition. Comparing it with these validation results would mix conditions.

## What we held fixed

Both runs used digits images, four layers of 1,000 gates, tau 10, Adam with
learning rate 0.01, batch size 100 and **60 final epochs**. Model seed and
validation split seed were both zero. The partition contained **1,077 training,
270 validation and 450 deferred-test images**. Both ran on CPU with
`OMP_NUM_THREADS=1` and `MKL_NUM_THREADS=1`.

The penalty weight was the intended changing setting. Data identities, saved
validation order, architecture, budget, versions and source fingerprints were
matched. We used the final checkpoint, not an earlier epoch selected after
looking at its validation score. Neither run performed test inference or saved
test inputs/labels; test metric fields remain null.

## Results and a concrete example

| Validation measurement | Control lambda 0 | Penalty lambda 0.1 |
|---|---:|---:|
| Soft recognition accuracy | 92.2222 percent | 91.4815 percent |
| Hard recognition accuracy | 92.2222 percent | 90.7407 percent |
| Correct hard predictions | 249 of 270 | 245 of 270 |
| Soft-to-hard accuracy gap | 0 percentage points | 0.7407 percentage points |
| Settled gate-output changes | 373,910 | 346,963 |
| Change opportunities | 1,076,000 | 1,076,000 |
| Changes per gate per adjacent image pair | 0.347500 | 0.32245632 |
| Eligible under accuracy rule | Yes | No |

The denominator is `4000 gates × 269 neighboring image pairs`. The first of
270 images establishes state, leaving 269 transitions. The measured reduction
is `(373910 - 346963) / 373910 = 7.2068 percent`, or **26,947 fewer changes**.

For accuracy, 249 correct images become 245: four fewer out of 270, giving
`4 / 270 × 100 = 1.48148 percentage points`. The frozen policy permits only
one percentage point, so the minimum allowed accuracy is **91.2222 percent**.
The candidate's 90.7407 percent is below that floor. Lower switching cannot
override this eligibility check.

The one-point tolerance is our working experimental policy, not a professor
requirement. We keep it unchanged after seeing the result. Both runs report
hard PyTorch/NumPy score and class agreement, including the reference's
lowest-index tie rule. That is software-reference agreement; these new models
have not yet passed their own RTL or FPGA implementation checks.

## Reproduction using new output directories

The following commands reproduce the pair into **new** directories. They are
instructions, not another run performed while writing this note. Preserve the
policy and source snapshot before running; never overwrite either the primary
evidence or `runs/digits_w1000`.

```bash
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python scripts/train.py \
  --dataset digits --width 1000 --depth 4 --tau 10 --epochs 60 \
  --bs 100 --lr 0.01 --seed 0 --split-seed 0 --device cpu \
  --act-mode batch --defer-test --act-weight 0 \
  --selection-policy docs/experiments/validation-selection-v1.json \
  --out runs/step43_reproduce_control

OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python scripts/train.py \
  --dataset digits --width 1000 --depth 4 --tau 10 --epochs 60 \
  --bs 100 --lr 0.01 --seed 0 --split-seed 0 --device cpu \
  --act-mode batch --defer-test --act-weight 0.1 \
  --selection-policy docs/experiments/validation-selection-v1.json \
  --out runs/step43_reproduce_penalty

.venv/bin/python scripts/select_validation_models.py \
  --control runs/step43_reproduce_control \
  --candidates runs/step43_reproduce_penalty \
  --policy docs/experiments/validation-selection-v1.json \
  --out runs/step43_reproduce_selection.json
```

## Review status and limitations

No implementation change or bug fix was required to obtain this result. The
latest **285-test** regression result belongs to the completed step 4.10
verification; it is not a newly executed step 4.3 test run. The independent
experiment review passed: a separate scalar oracle matched every validation
score, class and exact change count; final checkpoints, selection, source
snapshots, evidence hashes and documentation also passed. No blocking finding
or production correction was required.

This is **one seed and one nonzero lambda**, not a sweep, repeatability result
or statistical demonstration of general benefit. The control's selection is
provisional within this pair, not a final paper model. We have not evaluated
test performance; the historically inspected digits test remains exploratory.

The activity metric counts unweighted settled learned-gate outputs. It excludes
mapped hardware restructuring, routed glitches, capacitance, clock power and
electrical measurements. No new resource, timing, power, energy or novelty
claim follows from this comparison.

Next, step 4.4 examines additional predeclared penalty strengths using validation
only, followed by repeated seeds in 4.5. A candidate may fail the accuracy
budget while still teaching us about the tradeoff; preserve that outcome.
